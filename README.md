# 灵乌乌 - Silphuu

> A "Fake" Geo-Distributed Edge Stateful Mesh.

## 名字来源

**Silphuu = Silph + uu**

- **Silph** —— 取自 **Sylph**，西方神话里的「风之精灵」，「灵」便是从这里来的。拼写上把 y 换成了 i，视觉与读音上都更具现代感。
- **uu** —— 即为「乌乌」。

两者交汇，便成了 **Silphuu（灵乌乌）**。这是一个以我的名字命名的博客系统。

风之精灵也寄托了我对它的期许：博客本该如风一般，轻盈灵动，随来随去。

---

## 为什么会有它

折腾过形形色色的博客系统，却始终拼凑不出自己心里想要的模样。自己又不喜欢写前端，特别是看到 React、Vue 之类的前端框架，简直头都大了。还得装一堆从未听说过的 npm、Node.js 之类的东西，装完依赖竟然有整整几百兆！剩下的最直观的感受，只有害怕。

直到 AI 发展起来，终于可以让它替自己去应付前端了。卸下包袱后，我终于能顺从自己的偏执，写一套属于自己的博客服务——Silphuu 就此诞生。

---

## 前方高能 ⚠

本项目基于自己对性能、网络流量以及硬盘大小的偏执追求产生，充满了“过度设计”和“核弹打蚊子”。

比如，浏览器还未普及 JXL 格式，哪怕只为自己一个用户也要用；明知 WebTransport 还不成熟、HTMX 4.0 还在测试版，这都不影响自己去尝鲜。

所以，这不是一个常规的博客系统。它的架构主打一个“随心所欲”和“放飞自我”——基本是作者梦到哪写到哪，怎么开心怎么来：

- **零数据库**：嫌数据库性能不够极致，比不上内存。评论等数据全放内存里读取，数据源只有一行行纯文本追加的 `events.jsonl` 日志。
- **抠门省流**：受不了哪怕多发一字节的“无用流量”。用自定义报文极致省流，靠 WebTransport 双向流完成节点同步。砍掉心跳包，终于了却执念——没数据更新时，0 字节空闲流量。
- **原生边缘**：设计之初就原生面向 CDN。多节点之间没有中心节点，也没有主从之分，相互靠游标增量同步。（立个 Flag：将来尽量让它支持 Mesh 拓扑！）
