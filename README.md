# 灵乌乌 - Silphuu

> A "Fake" Geo-Distributed Edge Stateful Mesh.

## 名字来源

**Silphuu = Silph + uu**

- **Silph** —— 取自 **Sylph**，西方神话里的「风之精灵」，「灵」便是从这里来的。拼写上把 y 换成了 i，视觉与读音上都更具现代感。
- **uu** —— 即为「乌乌」，这也是朋友对我的爱称。

两者交汇，便成了 **Silphuu（灵乌乌）**。这是一个以我的名字命名的博客系统。

风之精灵也寄托了我对它的期许：博客本该如风一般，轻盈灵动，随来随去。

---

## 为什么会有它

曾折腾过形形色色的博客系统，不过却从未拼凑出，一次自己心里想要的模样。自己真的不喜欢写前端！！特别是看到 React、Vue 啊之类的前端框架，感觉简直头都大了。还得去装一堆，从未听说过的 npm、Node.js 之类的东西，装完依赖占了我硬盘几百兆！？剩下的最直观的感受，只有害怕。

直到 AI 发展起来，终于可以让它替自己去应付前端了。卸下包袱后，我终于能顺从自己的偏执，写一套属于自己的博客引擎——Silphuu 就此诞生。

---

## 前方高能 ⚠

本项目基于自己对性能、网络流量以及硬盘大小的偏执追求产生，充满了“过度设计”和“核弹打蚊子”。

比如，浏览器还未普及 JXL 格式，哪怕只为自己一个用户也要用；明知 WebTransport 还不成熟、HTMX 4.0 还在测试版，这都不影响自己去尝鲜。

所以，这不是一个常规的博客系统。它的架构主打一个“随心所欲”和“放飞自我”——基本是作者梦到哪写到哪，怎么开心怎么来：

- **事件驱动**：站点上发生的变动，会化为一条条事件，一行行追加进 events.jsonl 日志，并可压缩为一份 snapshot.json 快照。
- **零数据库**：觉得数据库性能不够极致，比不上内存。评论、点赞、浏览量等数据全放进内存里读取，事件即为数据。
- **抠门省流**：接受不了哪怕多发一字节的“无用流量”。WebTransport 双向流同步、自定义报文、砍掉任何“心跳类包”——无数据更新时，0 字节空闲流量。
- **原生边缘**：设计之初就原生面向 CDN。页面静态化边缘直出，内置边缘缓存爆破。多节点之间没有中心节点，也没有主从之分。（立个 Flag：将来尽量让它支持 Mesh 拓扑！）
- **零构建链**：没有任何前端框架，也没有任何打包依赖。手写的 CSS 和 JS 的打包、缩略图和字体子集的生成，都由引擎自己完成。
